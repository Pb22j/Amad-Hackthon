Method

What is measured, and what is deliberately not

The subject is PolicyEngine.screen_request: the deterministic layer that reads a request before the model does. It returns one of three outcomes — reject (refuse outright), signal (allow, but record an injection signal for telemetry), or allow.

This layer is defence in depth, not the containment boundary. Identity is injected by the tool guard outside the model loop, and every financial action needs a signed confirmation. The tool guard remains the final containment boundary, but the request screener now records or rejects every attack shape represented in this suite instead of relying on that deeper layer to hide detection gaps.

Labelling by intent is the load-bearing choice. Labelling each case with whatever the detector already returns would score 100% and prove nothing. The expected labels were kept unchanged while the implementation was repaired; gap markers were removed only after the corresponding cases reached those pre-existing expectations.

Implemented remediation

What changed in the implementation

Credential intent is relational. A credential noun is rejected only when a disclosure or retrieval action targets it. Reset, storage, and product-education questions remain available in both languages.

English and Arabic share semantic rule shapes. Override, disclosure, protected-target, credential, identity, and tenant concepts can pair across languages, which also covers normal Saudi code-switching.

Normalization is explicit and bounded. Unicode format characters, Arabic diacritics and spelling variants, dotless-i, leetspeak, and character-separated words are normalized before matching.

Encoded input is inspected safely. Standalone Base64 candidates are decoded only when they are bounded, valid UTF-8, and predominantly printable, then screened through the same semantic rules as plain text.

Reproduce

Run it

amad-agent eval-security            # summary, exits non-zero on a regression
amad-agent eval-security --json     # full machine-readable report
pytest tests/security -m security   # the same dataset as a gate
python scripts/build_eval_report.py # regenerate this page

A mismatch carrying a known_gap reason is reported and tolerated; a mismatch without one fails the suite. If a gap is ever fixed, the run also fails until its marker is removed, so the file cannot quietly disagree with the code.
